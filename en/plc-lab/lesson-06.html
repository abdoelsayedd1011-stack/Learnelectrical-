Counters and comparison

Many machines are all about "counting": 6 cans per box, 100 turns per reel, the number of cars in a car park. In this lesson you will use the CTU and CTD counters and compare numbers with compare instructions, on machines that move in front of you.

1The CTU and CTD counters

  • CTU (count up): each time its input power changes from 0 to 1, the current value CV goes up by 1. When CV reaches the preset value PV, its bit (C0) becomes 1.
  • CTD (count down): it subtracts 1 with each pulse.
  • Reset: an R coil on C0 sets CV back to zero and the bit to 0.
A counter counts edges, not time: if a can stays in front of the sensor for a minute, it is counted only once. So the counter has an edge built in. But note: a sensor that flickers (bounce) will be counted several times.

3Compare instructions

A compare goes in place of a contact: if the condition is true, power flows. You can compare a counter value (C0), a timer time (T0) or an analog value (MW10).

SymbolMeaningExample
==EqualC0 == 3
<>Not equalC0 <> 0
> and >=Greater than, greater than or equalMW10 >= 80
< and <=Less than, less than or equalT0 < 2.5
On site: never use == with analog values (temperature, level): the value can jump from 79.9 to 80.1 without ever being exactly 80. Use >= or <=.

In the simulator: choose Compare in the cell, then the address (C0), the condition and the number.

4Common faults on site

Common program and site faults:
  • The counter counts too many: the sensor flickers (shiny can, vibration). The fix: a short TON timer as a debounce, or adjust the sensor.
  • The counter does not count at all: the sensor is stuck at 1 (covered in dust), so there are no edges.
  • The box gets one can too many: the conveyor stops too late, or the sensor is before the drop point and the next can gets through. Sensor position matters as much as the program.
  • The counter went back to zero by itself after a power loss: the counter is not retentive. If the count matters (a production counter), make it retentive.

1What is a gateway, and why do we need one?

The PLC speaks Modbus or PROFINET inside the plant; the cloud speaks MQTT and HTTPS. The gateway is the device that sits between them: it reads from the operational technology (OT) side using the industrial protocol, converts the values to JSON, and publishes them over MQTT to the server.

  • Off-the-shelf hardware: Siemens IOT2050, Moxa, Advantech, Red Lion, Phoenix Contact, or an industrial Raspberry Pi. All are small Linux computers with two Ethernet ports: one for the plant network and one for the IT network.
  • The most popular software: Node-RED, a browser-based flow editor in which you drag nodes and wire them together. It is free and supported by almost every vendor.
  • Alternatives: Kepware (KEPServerEX), with drivers for hundreds of devices; Ignition Edge; Telegraf; or Python code using the pymodbus and paho-mqtt libraries.
Golden rule: in most applications the gateway only reads from the PLC. Writing from the cloud to the machine requires a dedicated security design and should be enabled only as a deliberate decision.

2A typical Node-RED flow

The flow you will build in the simulator is the same one that runs in real plants:

  1. Modbus Read (or S7, or OPC UA): address 192.168.1.10, port 502, unit 1, function FC3, start 0, 10 registers, every 1000 ms.
  2. Function: a short JavaScript snippet that turns the array of raw numbers into an object with meaningful names and correct units:
    const r = msg.payload;
msg.payload = {
  ts: Date.now(),
  oven_temp: r[0] / 10,      // 1825 → 182.5 °C
  parts_count: r[1],
  running: (r[2] & 1) === 1,
  current_a: r[3] / 100
};
return msg;
  3. Filter / RBE (Report By Exception): publish only when the value changes, saving 90% of messages.
  4. MQTT Out: topic plant/line3/oven on the broker over TLS, QoS 1, without Retain for process data (and with Retain for the status message).

Always add a Catch node for errors, and a Last Will message in the MQTT settings that reads “offline” if the gateway goes down.

3Buffering and offline operation

Plant internet connections drop. A good gateway buffers values locally (store and forward) during the outage, then sends them in order once the connection returns, carrying their original timestamps rather than the time of sending.

  • Synchronise the device clock with NTP; a wrong timestamp corrupts every chart.
  • Monitor the buffer size: a one-week outage at one reading per second = 600,000 records.
  • Send a heartbeat message every minute; its absence at the server = a “gateway not responding” alarm.

4Gateway security

  • Two separate Ethernet ports, with no routing between the machine network and the internet. The gateway is the only point that crosses the boundary.
  • Firewall: outbound only, to the broker on 8883; no inbound ports open from the internet.
  • Change the default Node-RED password, enable HTTPS for its editor, and restrict access to the maintenance network.
  • One certificate per gateway (not a single password for the whole plant), so that a single device can be revoked.
  • Regular updates to the gateway OS, and a backup of the flow file flows.json.

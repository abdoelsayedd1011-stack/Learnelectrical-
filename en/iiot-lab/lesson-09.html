OPC UA

The common language of the plant: instead of “register 40011 = 4998” you read “oven temperature 182.5 °C, quality Good, 12:40.” This is how monitoring systems talk to any PLC.

▶ The lesson in 5 minutes

Illustrated explanation, the simulator task solved, and the quiz answered. Made for the phone.

1Why OPC UA?

In Modbus you read 40011 = 4998, and it is up to you to know what it means. In OPC UA you read OvenTemp = 182.5 °C, with its timestamp and quality.

The server is the PLC itself or software like KEPServerEX. The client is SCADA, Node-RED or Ignition. And the address is written like this: opc.tcp://192.168.1.10:4840.

It is a common language for all vendors, with encryption and authentication built in.

2How is data organised in OPC UA?

Everything is a node in a tree, and each node has an identifier called a NodeId, like ns=3;i=1005 or ns=3;s="Line3".OvenTemp.

Each reading carries three things: the value like 182.5, the quality which is Good, Bad or Uncertain, and the timestamp taken at the source.

Bad quality means the cause is in the sensor or the PLC, not the network.

3What is the benefit of subscribing?

Instead of the client asking every second, it requests a subscription: the server sends the value only when it changes, and by more than a deadband. That is less load on the PLC.

The other services: Browse to see what is inside Line3. Read / Write to read OvenTemp or write Setpoint = 185. Call to run a method like StartBatch(recipe=7). And History read to read the temperature over the last hour.

4How is the connection secured?

Each side has an X.509 certificate. The first connection is always rejected until you trust the certificate manually.

BadCertificateUntrusted: move the certificate from the Rejected folder to Trusted. BadUserAccessDenied: check the user or their rights.

The None policy is for the lab only; in production use Sign & Encrypt. And sessions are limited (for example 32) and may need a separate licence.

5How do we enable it on an S7-1500?

First tick Activate OPC UA server in the CPU properties. Then create a server interface with only the variables you need. Then choose the runtime licence.

Finally download the project, open UaExpert and accept the certificate.

On the simulator: browse the tree, read value, quality and time, subscribe with a deadband, write a setpoint, and fix a rejected certificate. Open the simulator →

OPC UA

The common language of the plant: instead of “register 40011 = 4998” you read “oven temperature 182.5 °C, quality Good, 12:40.” This is how monitoring systems talk to any PLC.

1Why OPC UA?

The networks covered so far carry registers and bits: register 40011 holds 4998, and it is up to you to know that this is the frequency and must be divided by 100. OPC UA (Open Platform Communications Unified Architecture) carries meaningful information: a variable named OvenTemp, of type Double, in °C, with the value 182.5 plus its timestamp and quality. That is why it has become the common language between PLCs, SCADA, MES and gateways, regardless of vendor.

  • Server: exposes the data: the PLC itself (S7-1500, Beckhoff, B&R, Omron NJ) or middleware (KEPServerEX) that converts Modbus/PROFINET to OPC UA.
  • Client: reads, writes and subscribes: SCADA, Node-RED, Ignition, a dashboard.
  • Endpoint: opc.tcp://192.168.1.10:4840 (standard port 4840).
  • Platform-independent: runs on PLCs, Windows, Linux and in the cloud, with built-in encryption and authentication.

2Address space and NodeId

Everything in the server is a node in a tree: objects, variables, methods, types. Each node has a unique NodeId made of a namespace (ns) and an identifier, either numeric ns=3;i=1005 or string ns=3;s="Line3".OvenTemp. The client browses the tree downward from Objects, then reads, writes or subscribes.

Every value arrives as a triple: the value, its quality (Good / Bad / Uncertain) and the source timestamp. If the quality is Bad, the cause lies in the sensor or the PLC, not the network.

3Subscriptions instead of polling

Rather than asking “what is the value?” every 100 ms (polling), the client creates a Subscription with a publishing interval (for example 500 ms) and adds monitored items to it. The server then sends a value only when it changes, with a deadband (send only if the change exceeds 0.5) and a queue for fast changes. This greatly reduces the load on the PLC.

4Security: certificates and policies

OPC UA was designed with security built in: every server and client has an X.509 certificate that identifies it, and they agree on a security policy (None, Basic256Sha256, Aes256_Sha256_RsaPss) and a message security mode (None, Sign, Sign & Encrypt). On the first connection the server rejects the client’s certificate until you trust it manually in the server’s trust list, and vice versa.

  • BadCertificateUntrusted: the certificate has not been accepted yet: open the server settings and move the certificate from Rejected to Trusted.
  • BadUserAccessDenied: wrong username or password, or the user lacks write permission.
  • The None policy is acceptable only for lab testing; in production use Sign & Encrypt, especially if data leaves the machine network.
  • The number of sessions and subscriptions on a PLC is limited (for example 32 sessions on an S7-1500, depending on the model), and the licence may be separate.

5OPC UA on the S7-1500, step by step

  1. In TIA Portal: CPU properties → OPC UA → Server → Activate OPC UA server, then select port 4840 and the security policy.
  2. Under Server interfaces, create an interface and drag in the variables you want to expose (DBs or tags). Do not expose everything.
  3. Runtime licenses → OPC UA: select the appropriate licence.
  4. Download, then on your PC open a client such as UaExpert at opc.tcp://<ip>:4840, accept the certificate on the CPU, and browse.

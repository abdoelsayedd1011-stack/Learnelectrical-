CAN bus, CANopen and DeviceNet

A bus born in cars that now runs cranes, servo drives and valve islands. A single multimeter reading (60 Ω) solves half of its faults.

1How does CAN work?

CAN came from cars. It runs on two wires, CAN_H and CAN_L, with a differential signal, 120 Ω at both ends, at up to 1 Mbit/s. Protocols are built on top of it: CANopen for servos and cranes, DeviceNet at Allen-Bradley, and J1939 for heavy machinery.

The line has two states. Recessive (1): both wires at 2.5 V. Dominant (0): H at 3.5 V and L at 1.5 V.

Arbitration: dominant beats recessive, so the message with the lowest identifier wins with no collision. There is no master: priority is by identifier.

To check termination, switch the power off and measure the resistance between H and L. 60 Ω means two resistors, which is right. 120 Ω means only one. 40 Ω means three. And ∞ means no termination or a broken cable.

Error counter: above 127 the node goes error passive, and above 255 bus off. The cause is usually a different baud or a poor cable.

3How does CANopen organise messages?

Each node has a Node ID from 1 to 127, and each message identifier is calculated from it:

COB-ID = 0x180 + Node 5 = 0x185

PDO is fast cyclic data, up to 8 bytes. SDO reads or writes one parameter, like 0x6040:00. NMT manages the node state, and PDOs only run in the Operational state.

Heartbeat is a message by which the node says it is alive. And EDS is the device description file.

4How is DeviceNet different?

DeviceNet is CAN with the CIP protocol, and the cable carries a 24 V supply with the signal. White and blue are CAN_H and CAN_L, and red and black are V+ and V−. The address is a MAC ID from 0 to 63, and the speed is 125, 250 or 500 kbit/s.

The NS LED sums up the state. Steady green: connected to a master. Flashing green: on the network with no master. Flashing red: timeout. And steady red: a duplicate MAC ID or bus off.

If the voltage at the far end of the cable falls below 11 V, strange faults appear, so add a power tap in the middle.

5How do you think through a CAN fault?

Start by measuring 60 Ω between H and L. Then measure the voltage with the bus idle: H and L near 2.5 V. If you see bus off, check the baud, the cable and a duplicate ID.

If the network drops when a certain machine runs, the cause is noise. If only the far nodes fail, the cause is voltage drop.

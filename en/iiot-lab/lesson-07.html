CAN bus, CANopen and DeviceNet

A bus born in cars that now runs cranes, servo drives and valve islands. A single multimeter reading (60 Ω) solves half of its faults.

1How does CAN work?

CAN (Controller Area Network) is a serial bus from the automotive world that has become the foundation of many industrial networks: CANopen (European drives and servos, cranes), DeviceNet (Allen-Bradley / ODVA) and J1939 (heavy machinery). Two wires, CAN_H and CAN_L, carry a differential signal, with a 120 Ω resistor at each end and speeds up to 1 Mbit/s.

  • Recessive bit (1): both wires sit at about 2.5 V. Dominant bit (0): CAN_H rises to 3.5 V and CAN_L falls to 1.5 V.
  • If two devices transmit at once, the dominant bit wins. This is how arbitration works: the message with the lower identifier (more leading zeros) wins and completes, while the other waits. No collision, nothing lost.
  • CAN has no master: any node transmits when the bus is idle, and priority is set by the identifier.

The easiest check on site: disconnect the power and measure the resistance between CAN_H and CAN_L with a multimeter. 60 Ω = two correct resistors (120 ‖ 120); 120 Ω = only one; 40 Ω = three; ∞ = no termination or a broken cable.

Error counters: every node counts its own errors. Above 127 it enters Error passive (it keeps communicating but no longer signals errors); above 255 it goes Bus off (it withdraws completely until reset). A single node in Bus off usually means its baud rate differs from the others or its cabling is poor.

3CANopen: identifiers and objects

  • Each node has a Node ID from 1 to 127 (DIP switches or a parameter).
  • The message identifier, the COB-ID, = function code + Node ID. For example, the first transmit PDO from node 5: 0x180 + 5 = 0x185.
  • PDO (Process Data Object): fast cyclic data (status, speed) with no extra overhead, up to 8 bytes.
  • SDO (Service Data Object): reads and writes any parameter in the object dictionary at an address such as 0x6040:00 (the controlword in the CiA 402 drive profile).
  • NMT: the master (or the PLC) switches nodes between Pre-operational, Operational and Stopped. A node transmits PDOs only when Operational.
  • Heartbeat / Node guarding: every node announces that it is alive; if one goes silent, the master raises an alarm.
  • An EDS file describes the object dictionary (the counterpart of GSD).

4DeviceNet: the key difference

DeviceNet uses the same CAN layer but with the CIP protocol (the same one used by EtherNet/IP) and a dedicated five-wire cable: the signal pair (blue CAN_L / white CAN_H), a 24 V DC power pair (red V+ / black V−) and a shield. Power runs in the same cable and supplies the field devices.

  • MAC ID addresses from 0 to 63, and speeds of 125 / 250 / 500 kbit/s, usually set manually on each device.
  • Network status (NS) LED: steady green = online and allocated to a master; flashing green = online with no master; flashing red = connection timeout; steady red = duplicate MAC ID or Bus off.
  • Measure the supply voltage at the far end of the cable: below 11 V causes strange faults in remote devices (voltage drop along a long cable). The fix: an additional power supply in the middle.

5Reasoning through a CAN fault

  1. Check for 60 Ω between H and L with the power disconnected. Any other value points you to the termination or the cable.
  2. With a multimeter and the bus idle: CAN_H ≈ CAN_L ≈ 2.5 V (measured to GND). If either reads 0 or 5 V, there is a short to ground or to the supply.
  3. A single node in Bus off: its baud rate, its cable, or a duplicate Node ID.
  4. Everything drops out when a particular machine starts: noise from a power cable. Ground the shield at one end only and route the cable away.
  5. Only the remote devices fail on DeviceNet: supply voltage drop.

PROFINET

Almost every new Siemens panel runs PROFINET. The secret is the device name: set the names correctly and draw the topology, and TIA Portal will tell you which cable is in the wrong port.

1From PROFIBUS to PROFINET

PROFINET is the successor to PROFIBUS on Ethernet (100 Mbit/s, usually green cable, RJ45 or M12). The principle is the same: an IO-Controller (the PLC) exchanges cyclic data with IO-Devices (I/O modules, drives, robots). But instead of an address from 0 to 125, each device now has a device name and an IP address. And because it is standard Ethernet, an HMI, OPC UA and Modbus TCP can all run side by side on the same network.

ClassCycle timeUse
RT (Real-Time)1 – 10 msMost I/O and drives
IRT (Isochronous RT)Down to 250 µs, jitter < 1 µsMotion control; requires IRT-capable switches
TCP/IPNon-deterministicConfiguration, diagnostics and parameters

2Name first, then IP

The controller locates its devices by name using the DCP protocol, then assigns them the IP address configured in the project. Hence the commissioning sequence:

  1. In TIA Portal: add the device (from its GSDML file, the XML successor to GSD) and give it a name such as vfd-line3 and an IP address.
  2. On the physical device: Assign device name from TIA Portal (Online → Accessible devices) or with the PRONETA tool. Some devices have their name set by switches or a display.
  3. Download the project to the CPU. It assigns the device its address and data exchange begins.
Naming rules: lowercase letters, digits and hyphens only; no spaces, no capitals, and it must not start with a digit. The name is stored in the device; when replacing a failed unit, set the same name and it picks up everything else automatically. (Alternatively, enable Device replacement without exchangeable medium together with the topology, and the CPU identifies the device by its position in the network.)

3Topology and switches

  • Most PROFINET devices have a built-in two-port switch, so you can daisy-chain a line from device to device. But if a cable breaks in the middle, everything beyond it is lost.
  • A star from a managed switch is more robust, and a ring with MRP (Media Redundancy Protocol) tolerates a single cable break: one device acts as MRP Manager, keeping the ring logically open and closing it within 200 ms when a break occurs.
  • Switches: use industrial switches with PROFINET support (LLDP, VLAN priority). Cheap office switches often work with RT but fail with IRT and diagnostics.
  • LLDP lets every device know its neighbor on each port, so TIA Portal can draw the actual topology and compare it with the design: a cable in the wrong port shows up immediately.

4LEDs and diagnostics

LEDMeaning
BF steady redNo link on any port, or the controller was not found
BF flashingDevice present but no data exchange: name mismatch, IP conflict, or a device in the project that does not physically exist
SFDiagnostic: missing module, wire break on a channel, sensor supply fault
MT (Maintenance)Maintenance warning: a cable or port is dropping frames (approaching the error limit)
Link / P1 P2Per-port LED: green = link, flashing = activity

In TIA Portal, the Diagnostics buffer logs every device dropping out and returning, with timestamps, and Online → Devices & networks colors each device green or red. The free PRONETA tool scans the network, shows names, IP and MAC addresses, and lets you assign names without a project.

5Common PROFINET faults

SymptomCause
A new device does not appearThe name was not assigned on the device, or contains a capital letter or space
BF flashing after replacing a deviceThe replacement carries an old name from another machine: reset it to factory settings and assign the name
Communication drops every few minutesDuplicate IP with an office PC on the same network, or unshielded cable next to a drive (watch MT)
All devices beyond a certain point have vanishedLine topology with a cable broken in the middle
IRT does not workAn ordinary switch in the path does not support IRT, or the project topology does not match the installation

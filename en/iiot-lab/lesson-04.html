Modbus TCP

If you understand Modbus RTU, you already understand 90% of Modbus TCP. The rest is an IP address, a small header and a few traps such as word order.

1What changed from Modbus RTU?

Modbus TCP is the same protocol, but it travels inside TCP on port 502. So there is no baud to set, no parity and no termination.

In RTU the line is RS-485, the address is 1 to 247, the check is CRC-16, and there is one master. In TCP the network is Ethernet or Wi-Fi, the address is the IP with port 502 and a Unit ID, TCP itself guarantees delivery, and several clients can connect at once.

2What is the MBAP header?

A header called MBAP is added before the request, followed by the usual request:

00 0100 0000 060103 00 6B 00 02

Transaction ID is a number that matches each reply to its request. Protocol ID is always 0. And Unit ID is the address of the serial slave behind a gateway; for a directly connected device it is 1, 255 or 0.

3How do we read a PLC from a laptop?

Start with ping to confirm the network. Then open a client on IP:502. Then request, with function 03 from address 0, ten registers.

Connection refused means the server is not enabled or there is a firewall. Timeout means a network problem (lesson 2). And a huge meaningless number means a 32-bit value, so swap the word order.

On the S7-1200 use MB_SERVER. On Schneider, register 0 is %MW0.

4What are the limits of Modbus TCP?

It is not deterministic, so it is not for E-stops or axis synchronisation. One request carries up to 125 adjacent registers.

The number of connections is limited, for example 8, and a new one after that is refused. And it has no encryption, so isolate the machine network.

5How does a TCP to RTU gateway work?

The gateway receives the request over TCP, reads the Unit ID to know which slave is meant, then sends it on the RTU line and returns the reply:

SCADATCP · Unit 2GatewayRTUSlave 2

Timeouts here usually come from the serial side.
